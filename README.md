# AWS Medallion ELT Pipeline (Bronze → Silver → Gold)

A personal learning project: a batch ELT pipeline in PySpark that follows the Bronze / Silver / Gold
(medallion) pattern used on AWS data lakes, with AWS Glue and Athena/Iceberg deliverables.

It runs on **synthetic data** generated by a seeded script. It is not based on any employer or client
data.

## Architecture

```
raw CSV (S3)  ──►  Bronze (parquet, all strings + ingest metadata)
                       │
                       ▼
                   Silver  typed, cleaned, de-duplicated (latest version wins)
                       │   └─► orders_quarantine  (rejected rows + reason)
                       ▼
                   Gold    daily_sales, customer_summary  ──►  Athena / Iceberg tables
```

| Layer | What happens |
|---|---|
| Bronze | Raw land as-is, partitioned by `_ingest_date`, plus `_ingested_at` and `_source_file` for lineage |
| Silver | Type casting, status/country normalisation, validation, de-duplication on `order_id` using `updated_at`, quarantine of bad rows with a reject reason |
| Gold | `daily_sales` (revenue excludes cancelled/returned) and `customer_summary` (lifetime orders and value) |

## What was tested, and what was not

- **Run and tested locally** with PySpark 3.5 (`pytest`, 5 tests): bronze typing, Silver de-duplication
  and quarantine, "latest version wins", Gold business rules, and an end-to-end run with a
  reconciliation check.
- **Written but not run on a live AWS account:** `glue/glue_job.py` (Glue entry point reusing the same
  modules) and `sql/athena_iceberg_ddl.sql` (Iceberg table DDL and a `MERGE` upsert for Athena).

## Run it

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt          # needs Java 11+ for Spark

python -m src.pipeline.generate_data --out data/raw
python -m src.pipeline.run --raw data/raw --lake data/lake --ingest-date 2026-11-26
pytest -q
```

Sample run on the generated data: 2,060 Bronze order rows → 1,944 Silver orders and 60 quarantined
(20 invalid timestamps, 15 missing customer ids, 25 non-positive amounts). The remaining rows are older
versions of orders that were updated later.

## Data quality problems injected on purpose

Duplicate order ids with late updates, negative amounts, unparseable timestamps, missing customer keys,
mixed-case statuses and country codes.

## Deploying on AWS (outline)

1. Upload `data/raw` to `s3://<bucket>/raw/`.
2. Zip `src/pipeline` and create a Glue job from `glue/glue_job.py` with `--extra-py-files`.
3. Run with `--RAW_PATH`, `--LAKE_PATH`, `--INGEST_DATE`.
4. Create the Iceberg tables with `sql/athena_iceberg_ddl.sql` and query with `sql/gold_queries.sql`.

## Layout

```
src/pipeline/   spark.py, generate_data.py, bronze.py, silver.py, gold.py, run.py
glue/           glue_job.py
sql/            athena_iceberg_ddl.sql, gold_queries.sql
tests/          test_pipeline.py
```
